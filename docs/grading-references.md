# 採点基準の出典と、実機マニュアルとの対応

このプロジェクトの閾値がどこから来ていて、実機の運用規定（NATOPS / AFI /
FAA AC）や DCS コミュニティの実装（Supercarrier 内蔵 LSO、MOOSE AIRBOSS）と
どこが同じでどこが違うかをまとめる。**数値を変えた記録ではなく、変える
ときに何と突き合わせるかの一覧**である。

凡例: **[P]** = 一次資料から直接読んだ値、**[S]** = コミュニティ・二次
資料、**[M]** = このリポジトリの実データで測った値。

出典（2026-09-25 時点で公開されているもの）:

- CV NATOPS NAVAIR 00-80T-105 (2009) §6.2 — Case I パターン
- LSO NATOPS NAVAIR 00-80T-104 (2009) §4.2, §7.3, §11.4 — グライドスロープ幾何、H/R、グレード記法
- F/A-18A-D NATOPS A1-F18AC-NFM-000 §8.2.10 / §7.3.2 — 艦上パターン、オンスピード AOA
- CNATRA P-1211 (T-45 CQ FTI, 2001) / P-816 (T-45C CV Procedures, 2014)
- AFI 11-2F-16V3 (1999) §3.24–3.28 — F-16 オーバーヘッド（現行 AFMAN は取得不可）
- AETC AFMAN 11-248 (T-6, 2006/2007) §5.5–5.8, Table 5.1
- FAA AC 91-79A / 91-79B、FSF ALAR Briefing Note 7.1、FSF Flight Safety Digest 2004-08
- DCS Supercarrier Operations Guide (ED) pp.70–71、MOOSE `Ops/Airboss.lua`

### LSO グレードと記法

- グレード [P] LSO NATOPS Fig. 11-4: `_OK_`（完璧）/ `OK` / `(OK)`（fair）/ `--`（no grade）/ `C`（cut）/ `B`（bolter）/ `WO`・`WOP`・`OWO`・`TWO` / `NC`。**NATOPS にグレード境界の数値は無い**（LSO の判断）。
- 点数 [P] P-1211: `_OK_` 5、`OK` 4、`(OK)` 3、`B` 2.5、`--` 2、`WO` 1、`C` 0。
- 記法 [P] LSO NATOPS 11.4: `( )` 少し、`_x_` 大きく、`[ ]` 指示に応答なし。位置接尾辞 `X`（グルーブ前 1/3）、`IM`、`IC`、`AR`、`IW`。偏差語 H / LO / F / SLO / LUL / LUR / DR / DL / EG / TMP / AFU / NESA / LIG …。
- このリポジトリ（`lso_grader.py`）は `OK / OK- / (OK) / _NO_GRADE_ / CUT` の 5 段階で、ランプ手前 3 秒の平均偏差（m）で HIGH / LOW / OFFLINE、速度比で FAST / SLOW を出す。`OK-` は NATOPS に無い独自の段階、`_OK_` は無い。**位置接尾辞（X / IM / IC / AR）を付けていない**のが規定との最大の差。

甲板高はこのサーバの実トラップでは未検証（`validated: false`）で、甲板基準の
接地検出が動き始めたのは 2026-09-06 以降、座標系が正しくなったのは 2026-09-26
（下記）以降なので、それ以前の「空母着艦」行は較正に使えない。**角度化する前に、
目標ワイヤー基準の幾何を実トラップで検証する**のが順序
（`scripts/validate_carrier_geometry.py`）。

### 艦の幾何と座標系（2026-09-26 に作り直し）

それまでの空母の偏差は、次の 4 つがそれぞれ単独でファクターを動かす状態だった。
どれも合成データ（`backend/tests/case1.py`: 本番と同じ海面基準 AGL・`on_ground`
無し・15 m/s で進む CVN_73）で再現し、直したうえでテストで固定してある。

| 問題 | 影響 | 直し方 |
|---|---|---|
| 取り込みが接地前 60 秒 / 2 nm | キスオフ（ブレイク）が記録に一度も入らない。Case I はキスオフからワイヤーまで 1.5–2 分 | 陸上と同じ 300 秒 / 8 nm（`approach.carrier_window_s`） |
| 高さに Tacview の AGL を使用 | AGL は海面基準で、甲板上で ~22 m。ランプで ~20 m「高い」 | 高度 − (艦の高度 + 甲板高) |
| アングルドデッキが +9°（右舷向き） | 実際の最終方位は BRC − 9.14°。18° ずれた軸で横ずれを測るので、ランプ 200 m 手前で ~60 m の「OFFLINE」 | AIRBOSS の `rwyangle` −9.1359（DCS の `USS_Nimitz_RunwaysAndRoutes.lua` が出典） |
| 艦を接地時刻の位置で固定 | 15 m/s の艦は 3 秒前に 45 m 手前にいる。3.5° で 2.8 m「低い」、キスオフの位置は km 単位でずれる | 各サンプル時刻の艦位置・艦首方位で目標ワイヤーを置き直す（艦と一緒に動く座標） |

あわせて、グライドスロープの終点をランプ（艦尾）ではなく **3 番ワイヤーの 2 m 上**
に置いた（AIRBOSS `_GetOptLandingCoordinate`: 機体の基準点はフックより前にあるので
3 番ワイヤーで代表させ、甲板上の基準点の高さ 2 m を足す。本番の甲板上の記録
22.00 m MSL − 甲板 20.15 m = 1.85 m とも合う）。ランプ基準のままだと、ボールに
乗ったパスがランプで 3–5 m「高い」。ニミッツ級（CVN_71/72/73/75）の値:

| 値 | carriers.yaml | 出典 |
|---|---|---|
| 甲板高 | 20.15 m | [S] AIRBOSS 20.1494（DCS `USS_CVN_7X.lua`） |
| ランプ（着艦区域の艦尾端） | 艦の基準点から −162.49 m / 右舷 9.38 m | [S] AIRBOSS sterndist −164、最終方位の右 9.5 m を艦の座標に直したもの |
| アングルドデッキ | −9.1359°（左舷） | [S] AIRBOSS rwyangle（DCS `USS_Nimitz_RunwaysAndRoutes.lua`） |
| 目標ワイヤー | ランプから 79 m（3 番） | [S] AIRBOSS wire1–4 = 55 / 67 / 79 / 96 m |

G の導出だけは甲板座標ではなく、接地時刻で固定した地面座標（`fixed_along` /
`fixed_lateral`）で行う。旋回中の艦の座標で微分すると見かけの力が乗るため
（コリオリ項は艦の旋回 1°/s・相対 150 m/s で 2ωv ≈ 0.5 G。テストでは甲板座標の
まま微分すると 0.3 G 超ずれ、地面座標なら 3 G の円旋回が ±0.05 G で出ることを確認）。

**空母の Case I パターンは測定と講評のみ**で、グレード（OK / OK- …）は従来どおり
ランプ直前の HIGH / LOW / OFFLINE / FAST / SLOW / POWER だけで決まる。FAST / SLOW の
基準速度は、取り込みが伸びても 350 kt のイニシャルが混ざらないよう接地前 60 秒に
限った（`lso_grading.approach_speed_window_s`）。

### ボルター・タッチアンドゴー・ウェーブオフ後の周回

キスオフはイニシャルからのブレイクにしか無い。これらの後はアングルドデッキ沿いに
600 ft まで上がってからダウンウィンドへ旋回するので、その旋回を「キスオフ」と
呼んだり、800 ft のイニシャル基準や水平旋回の決まりで指摘したりしてはいけない
（独立レビューで再現した誤り）。

- **入り方の判定**（`pattern_entry`）: ブレイク開始前 60 秒の間に、艦の後方
  （ランプより後ろ）・中心線から 1 nm 以内を、BRC の向きに 500 ft 以上で飛んで
  いれば `initial`（キスオフ）、それ以外は `turn`（ダウンウィンドへの旋回）。
- **甲板からの記録**（`pattern_starts_from_deck`）: 取り込みは前回の甲板接触で
  止まるので、ボルター・タッチアンドゴー・発艦の後の記録は甲板の数 m 上から
  始まる。講評でその旨を述べる。
- **ウェーブオフ**（`pattern_low_pass_time`）: 甲板接触が無いので取り込みは
  前のパスまで遡る。そのまま脚を探すと記録中で一番長いダウンウィンド（前の
  パスのもの）を拾うので、接地より前にランプの上を 500 ft 未満で艦首方向へ
  通過した最後の時刻から後だけを測る。平面図では前のパスを淡い点線で描く。

### 着艦時の接地降下率（艦載機は硬く降りる）

艦上ではフレアしない。ボールに乗ったままワイヤーへ降ろすので、接地降下率は
グライドスロープの沈下そのもの（3.5°・閉合速度 57 m/s で 690 fpm）になる。
これを減点する理由は無いので、着艦では接地降下率を **測定して講評に書くだけ** に
している。逆に指摘するのはフレアの方: 最後の 1.2 秒の沈下がグルーブ中の沈下の
半分未満（`flare_sink_ratio`）なら「ランプで沈下を止めた」と講評する（浮いて
ワイヤーを越える、ボルターの原因）。脚の設計値（~24 ft/s = 1,400 fpm 前後）を
超える接地は「設計値を超える硬さ」と書く。どちらもグレードは動かさない。

### それより前の着艦記録の作り直し（rebuild）

作り直す前の空母の記録は、接地前 60 秒を上記の古い座標系（接地時刻で固定した艦・
右舷向きのアングルドデッキ・海面基準の AGL）で測ったものしか持っていない。
再採点（`POST /api/v1/landings/{id}/regrade`）は保存した進入をそのまま読み直すので、
キスオフを足すことも座標系を直すこともできない。

`POST /api/v1/landings/{id}/rebuild` は行に保存したものを使わず、DB に残っている
生の航跡（`tracks`）から作り直す（[`app/rebuild.py`](../backend/app/rebuild.py)）:

- 読む範囲は保存された接地時刻の 360 秒前から 60 秒後（取り込み窓 300 秒の前後に
  60 秒。対地速度の基線と、接地後の上昇・停止の判定に要る）。
- ライブ取り込みと同じ形に組み立て直す: 対地速度の導出と位置の飛びの除外は
  取り込みと同じ関数、空母は **同じフライトの全空母**（どの甲板の上かは検出器が
  決める）、AGL も OnGround も無い録画では最寄りの艦か静的オブジェクトの高度を
  地面にする。
- 今の検出器で切り出し、保存された接地時刻が「最初の接地 − 2 秒 〜 接地 + 2 秒」に
  入るイベントだけを同じ着陸とみなす。別の着陸で行を書き換えるくらいなら、何も
  書かない方がよい。
- 検出が決めるものはすべて書き直す（種別・結果・接地時刻と位置・進入の記録・
  グレード・点数・講評・ファクター・メトリクス・パターン・どの艦か）。
  `grading_version` は 7 になる。

作り直さずに 409 を返し、行をそのまま残す場合:

| コード | 意味 |
|---|---|
| `NO_RAW_TRACK` | 範囲内に生の航跡が無い |
| `NOT_AN_AIRCRAFT` | 航空機ではない。分類器を直す前に「着陸」として保存された降下傘の搭乗員（`Ground+Light+Human+Air+Parachutist`）など。作り直すと、今のライブ取り込みが拒む行をもう一度作ってしまう |
| `REBUILD_NO_MATCH` | 保存時刻に着陸が無い。艦の横で海面に落ちて「着艦」と保存された物体など（今の検出器はこれを着陸としない） |
| `NO_TOUCHDOWN_TIME` | 行に接地時刻が無い |

デプロイ後にまとめて流すのは [`scripts/refresh-landings.py`](../scripts/refresh-landings.py)
（標準ライブラリだけで動くので、サーバ上の python3 に標準入力で流せる）。
空母の行は rebuild、作り直せなかった空母の行とそれ以外は regrade。既定は下見で、
`--apply` を付けたときだけ書き込み、書き込む前の行を JSONL に残す。

検証 [M]: 合成データ（取り込みと同じ ACMI 行を `TrackIngestor` に通して書いた
生の航跡）で、60 秒で保存した Case I がキスオフの 30 秒以上前からの記録に戻り、
ブレイク位置とアビーム距離が飛ばしたとおり（±80 m / ±30 m）でグレード OK に
なること、今の版の行（空母・陸上・AGL の無い録画）は作り直しても変わらないこと
（対地速度・G・グルーブ時間まで）を `backend/tests/test_rebuild.py` で固定した。
ローカルの実録画（`test_import.db`: AGL 無し、静的オブジェクト 7、空母なし）では、
生の航跡の読み戻しと静的オブジェクトからの地面基準（64.96 m）が実データでも動き、
離陸滑走を着陸と取り違えないことだけを確かめた。この録画に航空機の着陸は無く、
保存された 2 件は降下傘（`NOT_AN_AIRCRAFT`）なので、**実際の着艦記録での作り直しは
本番で未確認**。

| 接地帯 | 滑走路の最初の 1/3、500–3,000 ft | [P] AC 91-79A / 91-79B | 未実装（`distance_to_threshold` は保存済み） |
| ハードランディング | 600 fpm 以上、または Vacc 1.75–2.2 G（Airbus / Boeing AMM） | [P] FSF FSD 2004-08 | 接地降下率バンド: default 120/250/450/650、fighter 300/450/650/850 fpm [M]、carrier（艦載機）500/850/1100/1400 fpm（§5） |

## 3. 実機マニュアルの数値を採点に入れるときの優先順位（提案）

1. **陸上ファイナルの降下率ゲート**（≤1,000 fpm）: 一次資料が明確で、
   データも `agl` の差分から既に出せる。旋回中を除いたファイナル区間の
   最大降下率を測り、まず表示だけ足してから帯を決める。
2. **接地帯**（閾値から 500–3,000 ft）: `distance_to_threshold` が解決済み
   滑走路で保存されているので、接地点の閾値からの距離は出せる。
3. **空母のグルーブ時間**（15–18 秒）: グルーブ開始（ラインアップ・ウイング
   レベル）から接地までの秒数。AIRBOSS と同じ定義で測れる。
4. **空母の偏差を角度・4 区間へ**: 上記のとおり幾何の検証が先。
5. ブレイクの G・バンク: 規定値が無いので、まず §4 の測定を数か月分ためて
   分布を見る（部隊の流儀が数字になる）。

## 4. ブレイクの G（このセッションで追加した測定）

### 何を測るか

ACMI に加速度計の値は無い。位置（緯度・経度・高度）が約 5 Hz（実測: 中央値
0.21 秒間隔 [M]）で入っているので、滑走路座標系に直した位置に**局所 2 次
多項式**（前後 1 秒、Savitzky–Golay と同じ考え方）を当てて速度と加速度を
出し、比力 `f = a − g` の速度直交成分を `g` で割ったものを**法線荷重倍数**
とする（`app/grading/kinematics.py`）。水平定常旋回なら `1/cos(バンク角)`、
直線水平飛行なら 1.0 になる。

ブレイク区間（`pattern.py` が対地トラック角から切り出した脚）について
出す値:

| メトリクス | 意味 |
|---|---|
| `break_max_load_factor` | ピーク G |
| `break_mean_load_factor` | 区間全体の平均（ロールイン・アウトを含む） |
| `break_sustained_load_factor` | G を掛けている部分（ピーク超過分の半分以上）の平均 |
| `break_load_factor_std` | 同じ部分の標準偏差 = **G の変動**。一定 G で回れば小さい |
| `break_sustained_s` | その部分の長さ |
| `break_max_bank_deg` / `break_mean_bank_deg` | 記録の Roll から（ACMI に Roll がある記録のみ） |
| `break_entry_speed_ms` / `break_exit_speed_ms` / `break_entry_agl_m` | 入口速度・出口速度・入口高度 |
| `break_heading_change_deg` / `break_mean_turn_rate_deg_s` | 旋回量（+ = 右回り）と平均旋回率 |
| `break_start_along_m` | ブレイク開始位置（+ = 基準点の手前） |
| `base_max_load_factor` | ベースターンのピーク G |

すべて**測定のみで採点しない**。理由は §1・§2 のとおり一次資料に G の規定が
無く、あるのは「水平で回れ」と「バンク角」だけだから。バンク角の規定
（T-45 の 70–80°、T-6 の 45–60°）を G に直すと 2.9–5.8 G と 1.4–2.0 G で、
機体と部隊でこれだけ違う。ブレイクが水平だったかは既に
`break_altitude_spread_m` で採点している。

### 検証 [M]

`scripts/validate-load-factor.py` で、実 DCS 記録（ローカルのインポート
テスト DB、固定翼 6 機種 563,240 行、Roll あり 517,547 行）の水平旋回
サンプル（|Roll| 20–80°、|Pitch| ≤ 10°、垂直速度 < 速度の 10%）について、
軌跡由来の G と `1/cos(Roll)` の比を取った:

| | 値 |
|---|---|
| 比較サンプル数 | 72,644 |
| 比の中央値 / 平均 | 1.000 / 0.992 |
| p10 / p90 | 0.866 / 1.086 |
| ±10% 以内 | 77.3% |
| 機種別中央値 | E-3A 1.000、A-50 1.000、M-2000C 0.994、F-15E 0.986、F-16C 0.975、F/A-18C 0.950 |

戦闘機が 1 よりわずかに低いのは、`1/cos(Roll)` が「釣り合った水平旋回」
の値であり、実際の旋回は横滑り・ピッチ・減速を伴うため（つまり Roll 側の
仮定のずれで、導出の誤差とは限らない）。同じ記録で見えた注意点:

- 地上滑走中の Roll に 12,000–14,000° という壊れた値が入っている。
  バンク角の統計は |Roll| ≤ 180° に限っている。
- 量子化（保存時 1 cm 丸め）は 2 秒窓の 2 次フィットでは G に 0.02 未満
  しか出ない（`tests/test_kinematics.py`）。
- 隣接差分を 2 回取る素朴な方法だと同じ量子化が 1 G 級のノイズになる。
  窓を短くするときはこの検証を再実行すること。

### 本番の実着陸での分布 [M]（2026-09-25、デプロイ直後に全 1,723 件を regrade）

オーバーヘッド 872 件のうちブレイク脚を採点対象にできた 725 件（G が付いた
のは 723 件）。Roll はこの版から保存するので、既存行のバンク角は無い。

| メトリクス | 中央値 | p10 | p90 |
|---|---|---|---|
| ブレイク最大 G | 2.68 | 1.42 | 5.28 |
| ブレイク定常 G（n=682） | 2.33 | 1.41 | 4.45 |
| 定常部の標準偏差（G の変動） | 0.229 | 0.076 | 0.602 |
| G を掛けていた時間 | 12.6 s | 4.4 s | 35.2 s |
| ブレイク進入速度 | 282 kt | 60 kt | 432 kt |
| ブレイク進入高度 | 1,247 ft | 117 ft | 3,774 ft |
| ベースターン最大 G（n=835） | 1.91 | 1.35 | 5.82 |

機種別の最大 G 中央値: F-16C 3.04（n=180）、F/A-18C 3.12（96）、F-15C 2.78
（47）、Su-27 4.37（32）、F-14B 2.38（26）、ヘリコプター 1.3–1.5。
コミュニティの「350–400 kt で 3.5–4 G」に対し、このサーバの戦闘機の中央値は
3 G 前後で、旋回率換算では 300 kt・3 G ≈ 11°/s。

同じ集計で見えた、数字を鵜呑みにしてはいけない点:

- **ブレイク脚の切り出しが伸びすぎる**ことがあった（v4 まで）。脚は
  「ダウンウィンドから遡って、イニシャル方向を向いていない間」だったので、
  ダウンウィンドの前に何か飛んでいれば全部ブレイクになった。実例: 75 秒の
  「ブレイク」、滑走路の 4.7 km 横で 457 kt・10.8 G の旋回（接地 174 秒前）、
  進入高度 20,097 ft、旋回量 501°。→ **v5 で修正**（次項）。
- **位置の飛び**が 9–12 G のスパイクになった（v5 まで）。実例: 高度が
  0.5 秒で 140 m 落ちて戻り、滑走路軸上の位置が逆走した記録（#599）。
  `MAX_PLAUSIBLE_LOAD_FACTOR`（15 G）は最悪の 2 点しか落とさず、窓に入る
  前後の点が 9–12 G を読んだ。取り込み側の 1,000 m/s の飛び判定より下
  （この例は約 670 m/s）。→ **v6 で修正**（「位置の飛びの除外」）。
- 一方で、位置が滑らかなまま 400 kt・30°/s（≈11 G、67 m AGL）の旋回も
  記録されている。DCS では起こるので、上限で切るのではなく、上の脚の
  切り出しを直して「ブレイクの G」から外すのが筋。
- regrade で点数が 0.05 以上動いた着陸が 27 件（グレードが変わった着陸は 0）。
  v4 は測定のみなので、v3 以前に採点されたまま残っていた行が現行規則で
  採点し直された分と考えられるが、旧版番号は上書きされたため未検証。

### ブレイク脚の定義（v5、2026-09-26）と修正後の分布 [M]

ブレイク脚は **ダウンウィンド前 90 秒（`break_lookback_s`）の中で、最後に
90° 以上（`min_break_turn_deg`）回った同一方向の連続旋回** とする
（`pattern.BreakBounds` / `_turn_runs`）。連続旋回は 5 秒（
`break_straight_tolerance_s`）を超える直進か、15°（
`break_reverse_tolerance_deg`）を超える逆旋回で切れ、210°
（`max_break_turn_deg`）・60 秒（`max_break_s`）を超える分は先頭から
落とす。遡りは「着陸方向に揃って直進している」点（イニシャル）で止まる。
90° に届く旋回が無ければ、いちばん大きく回った旋回を報告だけして採点しない。

「最後の連続旋回」ではなく「最後の 90° 以上の旋回」にした理由: 本番の
ブレイクの約 3 分の 1 は、130–150° の本体、数秒〜十数秒の一時停止か
ドッグレッグ、そして 30–40° のダウンウィンドへの寄せ、という二段階で
飛ばれていて、最後の連続旋回だとその寄せの方を「ブレイク」と呼ぶことに
なる（実例 #56 F-15C、#58 F-15E）。

同じ 872 件（v4 の値は上の表）に当て直した結果:

| メトリクス | v4（旧） | v5（新） |
|---|---|---|
| 採点対象のブレイク | 726 | 612 |
| 継続時間 中央値 / p90 / 最大 | 26.3 / 63.6 / 195 s | 25.1 / 39.9 / 60.0 s |
| 旋回量 中央値 / p10 / 最大 | 153 / 42 / 501° | 174 / 132 / 210° |
| 進入高度 中央値 / p90 / 最大 | 1,246 / 3,774 / 20,097 ft | 1,107 / 3,000 / 21,792 ft |
| 高度変動 中央値 / p90 | 516 / 2,642 ft | 552 / 1,912 ft |
| 最大 G 中央値 / p10 / p90 | 2.67 / 1.42 / 5.28 | 2.88 / 1.61 / 5.53 |
| 定常 G 中央値 | 2.33 | 2.45 |
| 進入速度 中央値 | 282 kt | 290 kt |
| 1% ルール目標 G 中央値（進入速度 kt ÷ 100） | — | 2.90 |
| 最大 G ÷ 1% 目標 中央値 / p10 / p90 | — | 1.03 / 0.73 / 1.79 |

F/A-18）と、位置の飛び（#599）の両方で、後者は次項の外れ値除去の仕事。

「1% ルール」（進入速度 kt の 1% を G で引く）に対しては、最大 G の中央値が
目標のちょうど 1.03 倍で、このサーバの戦闘機は平均するとその通りに
飛んでいる。個々には 0.7〜1.8 倍のばらつきがある。経験則（二次資料）
なので参考値として並べるだけで採点はしない。

### 位置の飛びの除外（v6、2026-09-26）[M]

各サンプルについて、そのサンプルを除いた前後 1 秒の 2 次フィットが予測する
位置と記録の位置との距離（leave-one-out 残差）を測り、
`max(10 m, 0.05 s × 速度)` を超える点を G の導出から外す
（`kinematics.reject_position_outliers`）。飛びは数点続くことがあるので、
捨てた点を窓から外して全点を測り直すのを最大 3 回繰り返す（1 回目には
飛びに引きずられた隣の正常な点も掛かるが、2 回目で戻る）。外した数は
`kinematics_rejected_samples` として評価メトリクスに出る。

閾値を時間で置く理由は、残差が速度に比例していたから。本番 300 記録・
264,305 サンプルの残差:

| 速度 | p90 | p99 | p99.9 | 残差 ÷ 速度 の p99 |
|---|---|---|---|---|
| < 100 m/s | 0.9 m | 4.9 m | 9.6 m | 0.10 s |
| 100–200 m/s | 1.6 m | 7.2 m | 20.0 m | 0.05 s |
| 200–300 m/s | 2.7 m | 11.4 m | 28.7 m | 0.05 s |
| > 300 m/s | 4.1 m | 28.0 m | 215 m | 0.08 s |

つまり通常のノイズは位置ではなく**タイムスタンプのジッター**（書かれた
時刻と位置の時刻が数十 ms ずれる）で、機体の運動が 2 次式から外れる分
（10 G・200 m/s の旋回でも 3 次項は約 4 m）よりずっと大きい。0.05 秒を
超える残差は 1 フレーム遅れの位置（0.2 s = 140 m/s で 28 m）、別軌跡の
混入（#599: 93 m/s で 109 m）、200 m/s で 10 m 級のスタッターの塊
（#1433: 2 秒の中で 1 G → 10.7 G → 3 G → 9.6 G → 2 G）のいずれか。

閾値の当たりは 300 記録＋参照 6 件で振って決めた:

| 設定 | 除外率 | ブレイク最大 G 中央値 / p99 / 最大 | #599 | #1433 | #1750 |
|---|---|---|---|---|---|
| なし | 0% | 2.71 / 10.81 / 12.52 | 12.52 | 10.68 | 12.14 |
| 0.10 s / 10 m | 0.15% | 2.69 / 10.05 / 12.14 | 2.75 | 9.19 | 12.14 |
| **0.05 s / 10 m** | 0.28% | 2.69 / 9.96 / 10.81 | 2.75 | 4.67 | 9.96 |
| 0.05 s / 5 m | 0.83% | 2.62 / 9.96 / 10.81 | 1.6 | 4.67 | 9.96 |

床を 5 m まで下げると中央値が動く（正常な点を捨て始める）ので、中央値を
変えずに飛びだけ落とす 0.05 s / 10 m を採った。840 件全体では除外 0.14%
（記録あたり中央値 0、p90 3 点、最大 81 点）、最大 G の p99 が 9.19 →
8.90、最大が 12.52 → 10.81。残る 9 G 超（#1750 F-16 定常 8 G、#1810 Su-27
10.8 G で除外 0 点、#1127 F/A-18 10.0 G）は位置が滑らかで、記録上は実際に
そう飛んでいる。

局所の実記録（`test_import.db`、Tacview クライアント録画）では除外 0 点で、
ジッターは本番のリアルタイム配信側の性質。Roll との突き合わせの結果は
変わらない（中央値 1.000、±10% 以内 77.3%）。

### まだ検証していないこと

- Roll の符号規約（Tacview 仕様では右バンクが正）。統計は絶対値で取って
  いるので結果には影響しない。
- 記録の Roll から取るバンク角の分布（保存はこの版から）。
- 進入高度 21,792 ft の 1 件（v5 でも残る）: 210° に切った後も高高度からの
  スパイラルの最後の半周を「ブレイク」と呼んでいる。パターン高度の上限で
  弾くかどうかは、規定値が機体ごとに違う（800 / 1,500 ft AGL）ので未決。

## 5. 艦載機の接地降下率（陸上、2026-09-26）

陸上の採点で F/A-18・F-14・Su-33 などを `fighter`（300/450/650/850 fpm）で見ると、
艦載機の教科書どおりの接地が減点される。艦載機は硬く降りる前提で作られ、そう
飛ばれるため:

- 艦上ではフレアしない。陸上でも FCLP（field carrier landing practice）は同じ
  降ろし方で、グライドスロープは 3.0–3.25° [P] LSO NATOPS 4.2.7。オンスピード
  ~135 kt の Hornet なら 135 × 101.3 × tan 3° = **716 fpm**（計算）。
- 陸上の通常着陸でも、接地直前にパワーを足して沈下を和らげる程度で、F-16 の
  ようなアイドルのフレアとは違う [S] 海軍パイロットの証言（f-16.net）。
- 脚の設計: 艦載機の脚は陸上機より強く作られ、US Navy 機は 24 ft/s 前後の
  沈下を想定する [S]。F-35C の落下試験は 26.4 ft/s [S] Wikipedia "Drop test"。

そこで `airframe_classes.carrier`（`fighter` より先に照合。Su-33 が `fighter` の
"Su-3" に取られないため）と専用バンドを置いた:

| バンド | fpm | 意味 |
|---|---|---|
| excellent | 500 | パワーで和らげた陸上接地 |
| good | 850 | FCLP: フレア無しで 3.0–3.5° のグライドスロープのまま |
| fair | 1,100 | グライドスロープだけでは説明できない硬さ |
| hard | 1,400 | 脚の設計値（~24 ft/s）に近い |

どの節も `fighter` 以上なので、艦載機クラスへ移って点が下がる着陸は無い
（`test_the_carrier_band_never_scores_below_the_fighter_band`）。716 fpm の FCLP は
`fighter` で 47 点「hard」、`carrier` で 88 点「good」。**このサーバの F/A-18C /
F-14 の陸上着陸の分布ではまだ確かめていない**（本番 DB を読めなかったため）。
AV-8B（トラップしない。垂直着陸は沈下をほぼ 0 まで落とす）と F4U（レシプロで、
陸上では他のウォーバードと同じくフレアして三点着陸）は対象外にしてある。
